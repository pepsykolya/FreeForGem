# nebgpu (ядро FFGN) — бинарники для хоста

Исходник ядра закрыт (репо ffgn-kernel, сюда не класть). Контракт — `nebgpu.h` (API 1). Версия: `nebgpu_build_info()`.

| файл | что |
|---|---|
| `linux-x86_64/libnebgpu.so` | CUDA runtime статически, нужен только glibc ≥ 2.17 (проверено objdump -T), без libstdc++; sm_61..sm_120 + PTX |
| `windows-x64/nebgpu.dll`, `nebgpu.lib` | то же для Windows x64 (MSVC /MT, зависит только от KERNEL32), импорт-библиотека для линковки |

Минимальный цикл хоста: `nebgpu_open(dev)` → `nebgpu_selftest` → `nebgpu_load_datasets_file(весь файл)` →
на Model frame `nebgpu_set_model_packed(ctx, index, packed, len)` (сборка таблицы: KEP1 ~20 мс, RET2 ~0.16 с на 3070; те же веса — no-op) →
`nebgpu_scan(...)` пачками ~0.2–1 с → каждый хит перепроверить `nebgpu_ref_ticket` → Share/Submit.
`nebgpu_scan`/`set_model` = `NEBGPU_E_COMPUTE` → карта считает неверно: откат разгона/UV, хиты вызова выбросить, set_model заново.
Индексы CUDA: задайте `CUDA_DEVICE_ORDER=PCI_BUS_ID`, чтобы совпадали с nvidia-smi.
v0.2.8.1 (18.11.2026): ожидание GPU без кручения CPU (событие cudaEventBlockingSync), остальное = 0.2.8.
Скорость v0.2.8 (боевой датасет, сток): RTX 3070 KEP1 ≈ 17.0 M попыток/с, RET2 ≈ 9.9 M/s; RTX 4070 Ti KEP1 ≈ 37.4, RET2 ≈ 17.7. Частоту ПАМЯТИ не снижать (810 МГц = −90 %, 5001 = −25 %); ватты экономить локом ядра. bench/canary с ds=-1 работают без модели.
v0.3.0 (19.11.2026, ffgn 1.0.6): нулевые строки таблицы (E = 0) не читаются (NEBGPU_DEADSKIP=0 — читать); ядро KEP1 выбирается на каждой новой модели замером на первых запусках scan (опция 4 / NEBGPU_KEP1_PATH как раньше). Бит-в-бит. 3070 (модели цепи, лок 1650): Kepler 19.3, TESS 25.9 M/s.
v0.4.0 (20.11.2026, ffgn 1.0.7): нулевые строки не читаются и в narrow-свёртке; KEP1 warp использует одну попытку на warp/block. Бит-в-бит. 3070 (модели цепи, лок ~1680): Kepler 31.4, TESS 37.9 M/s; TESS 40.49 M/s при 1850 МГц, лучшая измеренная эффективность 0.271 MA/W при 1680 МГц. Production layout 1; точная F2-упаковка layout 8 измерена как медленная и остаётся только opt-in экспериментом.
v0.5.1 (20.11.2026, ffgn 1.0.8): KEP1 warp — широкие строки в быстром пути conv, предвыборка хвоста строки в L2, 16 warp/SM (WK_MINB по архитектуре: 1 на sm_80/sm_100+), ключи попыток пишутся слитно; на слоте, где живая таблица больше L2 (CC ≥ 8.0, warp), сортированный и обычный порядок попыток замеряются на первых запусках каждой модели, сортировка остаётся при выигрыше ≥ 2 % (буферы на контекст; NEBGPU_SORT=0|1 — принудительно, только тесты). Бит-в-бит. 3070 (модели цепи, 1680/+210/200 Вт, одна сессия с 0.4.0): Kepler 31.37 → 38.22 M/s (0.1905 → 0.2064 MA/W), TESS 36.81 → 41.67 (0.2463 → 0.2524 MA/W); при 1620/+240: Kepler 37.23 (0.2215 MA/W), TESS 40.20 (0.2752 MA/W). 4070 Laptop: явных изменений нет (в пределах теплового разброса ноутбука; 6 пар A/B 0.4.0→0.5.1: скорость +0.8…+5 %, выигрыш не заявляем).
v0.6.0 (21.11.2026, ffgn 1.0.9): на CC ≥ 7.5 путь выбирается автоматически для каждого слота и модели — таблица дайджестов (попытки с ≤ 2 живыми строками берутся из таблицы модели, сборка 0.2–1.1 с, инкрементально часто 0.1–0.7 с; быстрый скринер нонсов, DTV=3), дешёвый фильтр k=3..6 (по замеру скорости, при NVML — и на ватт) или обычный путь; таблица строится, если её ожидаемая скорость ≥ 0.8 × замеренной скорости полного пути, и выключается, если замер ниже. NEBGPU_AUTO=0 — пути 0.5.x. Новое: nebgpu_slot_path (путь слота и текст), nebgpu_eval_stats считает вычисленные попытки отдельно от проверенных нонсов — хост 1.0.9 показывает хешрейт как вычисленные попытки. Бит-в-бит (векторы, s1, selftest, random, autosub/dtsub/dtinc, mtscan; 4070 Laptop, 3070, CMP 50HX sm_75). 3070 1680/+210/200 Вт, живые модели: Kepler 55.6–76.8 MA/s при 111 Вт, TESS 184.3 MA/s при 112.7 Вт; CMP 50HX 1500 МГц: Kepler 59.8–82.3, TESS 196.9 MA/s при 132–135 Вт.
v0.6.1 (21.11.2026, ffgn 1.0.10): более быстрый скринер нонсов на пути таблицы дайджестов (k_dt_scan2, DTV=16 по умолчанию на CC ≥ 7.5; NEBGPU_DTV / опция NEBGPU_OPT_DTV = 13 — только тесты); вызовы, выбор пути и формат таблицы — как в 0.6.0; текст nebgpu_slot_path заканчивается на «, screener v<N>».
